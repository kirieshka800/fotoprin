# Аудио: Whisper, расшифровка и воспроизведение

Программа на Rust передаёт аудио вашему сервису распознавания Whisper. Ollama анализирует уже распознанный текст; сама модель qwen2.5 не принимает аудиофайлы.

## Если Whisper уже запущен в Docker

В PowerShell выполните:

```powershell
docker ps --format "table {{.Names}}\t{{.Image}}\t{{.Ports}}"
```

Определите имя образа и внешний порт. В строке `0.0.0.0:8000->8000/tcp` внешний порт — первое число, 8000. Если Rust запускается через `cargo run` на Windows, адрес сервиса обычно `http://127.0.0.1:ВНЕШНИЙ_ПОРТ`.

### OpenAI-совместимый сервис (например Speaches)

В `.env` рядом с `Cargo.toml` добавьте параметры, соответствующие вашему контейнеру:

```dotenv
WHISPER_URL=http://127.0.0.1:8000
WHISPER_PROVIDER=openai
WHISPER_MODEL=Systran/faster-whisper-small
WHISPER_LANGUAGE=ru
WHISPER_TIMEOUT_SECONDS=600
```

Адрес и модель в примере нужно заменить на фактические. Узнать модели OpenAI-совместимого сервиса можно так:

```powershell
Invoke-RestMethod http://127.0.0.1:8000/v1/models
```

Для Speaches (`ghcr.io/speaches-ai/speaches:latest-cpu`) на порту 8000 можно загрузить русскоязычную многоязычную модель так:

```powershell
Invoke-RestMethod -Method Post -Uri "http://localhost:8000/v1/models/Systran/faster-whisper-small" -TimeoutSec 600
```

Первая загрузка занимает время и требует доступа контейнера к Hugging Face. Затем проверьте список:

```powershell
(Invoke-RestMethod "http://localhost:8000/v1/models").data | Select-Object id
```

В `.env` используйте `WHISPER_URL=http://localhost:8000`, `WHISPER_PROVIDER=openai` и `WHISPER_MODEL=Systran/faster-whisper-small`. Имя `whisper-1` не равно имени установленной модели Speaches и может приводить к ошибке модели.

Если у вас другая установленная модель, скопируйте её точное имя в `WHISPER_MODEL`. Некоторые сервисы требуют предварительной загрузки модели по своей инструкции. Для провайдера с ключом добавьте `WHISPER_API_KEY` в свой локальный `.env`; в репозиторий ключ не загружайте.

Допустимы все три варианта адреса:

- `http://127.0.0.1:8000`
- `http://127.0.0.1:8000/v1`
- `http://127.0.0.1:8000/v1/audio/transcriptions`

Rust отправляет multipart-запрос с полями `file`, `model`, `language` и `response_format=verbose_json`, а также MIME-типом аудио. Ошибка подключения, неверная модель или ошибочный ответ отображаются в карточке встречи.

### whisper.cpp server

У whisper.cpp другой путь: `/inference`. Используйте:

```dotenv
WHISPER_URL=http://127.0.0.1:8080
WHISPER_PROVIDER=whisper_cpp
WHISPER_LANGUAGE=ru
```

Модель задаётся при запуске самого whisper.cpp server; `WHISPER_MODEL` этому серверу не отправляется. Для OGG/MP3 и других сжатых форматов запустите whisper.cpp с `--convert`; в его окружении должен быть FFmpeg. Иначе предварительно используйте поддерживаемый WAV-файл.

Документация сервера: https://github.com/ggml-org/whisper.cpp/tree/master/examples/server.

### Если у контейнера другой API

Если сервис принимает `/asr`, `/transcribe` или иной нестандартный маршрут, не подставляйте случайный адрес OpenAI API: совместимость зависит от формата полей и ответа. Посмотрите документацию именно вашего Docker-образа. Для настройки подключения нужны название образа и внешний порт, без паролей и токенов.

## Если Whisper не запущен

Запустите выбранный OpenAI-совместимый сервис или whisper.cpp по официальной инструкции. Его настройки должны соответствовать примерам выше. Один `ollama serve` Whisper не запускает. Приложение не скачивает и не запускает Docker-контейнеры автоматически.

Speaches: https://github.com/speaches-ai/speaches — используйте CPU/GPU-образ, подходящий вашей машине, и настройте модель по документации проекта. Rust-приложение остаётся отдельным процессом `cargo run`.

## Обновление и проверка

1. Сохраните изменения `.env`. Остановите старый Rust-сервер через Ctrl+C и снова выполните `cargo run`.
2. Откройте http://127.0.0.1:8081/new-meeting.html.
3. Загрузите короткую запись с отчётливой русской речью, например: «Заказ сто двадцать пять согласован. Контрольный оттиск нужно проверить завтра».
4. Сначала не добавляйте заметки: так проверяется именно аудио, а не анализ введённого текста.
5. Дождитесь обработки. Вкладка **Расшифровка** должна содержать произнесённый текст и таймкоды. Протокол должен опираться на распознанный текст.
6. В блоке **Спросить о встрече** задайте: «Какой заказ упоминается в записи?».
7. В AI-ассистенте спросите: «Что сказано в аудиозаписи встречи “НАЗВАНИЕ ВСТРЕЧИ”?». Для большого числа встреч уточните ID и используйте блок вопросов самой встречи.

Качество текста зависит от модели, шума и длины записи. Для русского языка нужна многоязычная модель, а не модель с суффиксом `.en`.

## Уже загруженные записи

Перезаливать файл не требуется. Откройте встречу → **Расшифровка** → **Распознать аудио**. Если предыдущая обработка завершилась ошибкой, такая же кнопка доступна в блоке ошибки. Повторная обработка использует сохранённый файл, исходные заметки и заново готовит протокол.

Если первоначально было разрешено создание задач и обработка не дошла до него, успешная повторная обработка создаст задачи. Уже созданные по этой встрече задачи повторно не добавляются.

При недоступном Whisper:

- Если заметок нет — встреча показывает ошибку обработки, сохранённую запись можно прослушать и повторно отправить на распознавание.
- Если заметки есть — саммари может быть готово по заметкам, но ошибка распознавания видна во вкладке расшифровки, а подпись указывает источник саммари. Программа не выдаёт заметки за распознанное аудио.

## Плеер

- Длительность определяется по самому файлу в браузере; фиктивной минуты больше нет.
- Пока длительность неизвестна, отображается `--:--`.
- По окончании записи кнопка переключается на воспроизведение; повторное нажатие начинает запись заново.
- Перемотка ограничена реальной длиной. Доступны стрелки клавиатуры, Home/End и изменение скорости.
- Если аудиофайла нет, воспроизведение отключено; имитация проигрывания не запускается.

Отображение использует целые секунды: запись длиной 3,96 секунды показывает 00:03. Значение из ответа Whisper не должно перекрывать действительную длительность медиафайла.

## Диагностика

- **Нет связи с Whisper**: проверьте `docker ps`, внешний порт и `docker logs ИМЯ_КОНТЕЙНЕРА`.
- **404**: проверьте провайдера и маршрут; OpenAI-совместимый `/v1/audio/transcriptions` отличается от whisper.cpp `/inference`.
- **Ошибка модели**: проверьте точное имя и наличие модели в вашем сервисе.
- **В записи не удалось распознать речь**: попробуйте отчётливую речь без музыки и проверьте выбранный язык.
- **Файл записи не найден**: при переносе проекта нужна исходная папка `uploads`; одна база данных не содержит аудиобайлы.
- **Бесконечная обработка после перезапуска**: обновите страницу; сервер помечает прерванные обработкой встречи ошибкой при следующем запуске, после чего доступен повторный запуск.

## Проверки разработки

`cargo test` включает проверку адресов сервисов, разбор сегментов и длительности. `tests/audio_integration.py` проверяет настоящий Rust/PostgreSQL и подставной Whisper (`tests/fake_whisper.py`) на порту 11436; сервер приложения запускайте с `WHISPER_URL=http://127.0.0.1:11436/v1` и `WHISPER_MODEL=test-asr`.

`tests/audio_browser.py` использует реальные WAV-файлы длиной 3 и 3,96 секунды: проверяет время вместо старых 60 секунд, окончание воспроизведения, повтор, перемотку, ошибку и кнопку распознавания. Дополнительно проверялся настоящий Whisper tiny CPU на коротком OGG: распознанный текст сохранился в PostgreSQL и передался в запрос AI. Сам анализ AI в автоматических интеграционных тестах использует подставной Ollama.
