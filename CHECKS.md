# Проверка доработки

Проверено 12 ноября 2026 года:

- `cargo build`: успешно, сервер остаётся на Rust/Axum/SQLx. Два предупреждения исходного кода (неиспользуемый импорт и метод), ошибок нет.
- `cargo test`: 15 тестов, 0 ошибок.
- `tests/assistant_integration.py`: 26 тестов, 0 ошибок. Настоящая отдельная PostgreSQL 17; подставной HTTP-сервис Ollama. Проверены оба формата OLLAMA_URL при разработке; финальный прогон использовал базовый URL.
- `tests/assistant_browser.py`: подтверждение, отказ, экранирование текста, ссылка на результат, перезагрузка и мобильный экран; ошибок JavaScript нет.
- `node --check`: assistant.js, api.js, config.js — успешно.

Исправлены результаты независимой проверки: отклонение графика проверяет отдых после восстановления; одно предложение графика нельзя разделить на независимо подтверждаемые карточки; новый комментарий отменяет устаревшее удаление задачи; карточка отклонения показывает восстановление/удаление каждой смены.

Проверка с настоящей локальной моделью Ollama в этой среде не выполнялась. Качество понимания конкретных запросов зависит от установленной модели. Программа не подключает реальную отправку почты или Telegram: как и раньше, напоминания появляются внутри приложения.

В ZIP нет .env, .git, .idea, target и пользовательских аудиозаписей. При обновлении сохраните свой .env, базу данных и uploads.

Дополнительный регрессионный сценарий: модель обещает готовое предложение, но возвращает actions=[]. Сервер повторяет планирование с обязательным непустым массивом действий, показывает карточку только с реальными параметрами и применяет пять смен после подтверждения. Если модель повторно не возвращает действия, сервер сообщает об ошибке и ничего не сохраняет. Проверено с подставным Ollama; реальная модель пользователя отдельно не запускалась.

Для явного запроса создания расписания схема модели ограничена только plan_shifts. Регрессионные тесты: четыре ошибочных read_all_notifications заменяются планом смен; повторное постороннее действие вызывает ошибку без сохранения карточек. Проверено на подставном Ollama.

Регрессионный сценарий создания задачи после обсуждения графика: два ошибочных publish_schedule заменяются create_task, повторные идентичные create_task объединяются в одну карточку, подтверждение создаёт задачу с ожидаемым названием и приоритетом. Повторное постороннее действие модели отклоняется. Последний явный запрос ограничивает допустимый тип операции.

Основной интерфейс доступен по /assistant.html без v=2. Браузерный тест проверяет Cache-Control: no-store для HTML и assistant.js и работу подтверждений по обычному URL. Последний прогон: 15 Rust-тестов, 26 HTTP-тестов, браузерная проверка, без ошибок.
