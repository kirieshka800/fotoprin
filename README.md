# Фотопринт AI

Рабочий помощник для команды типографии: встречи, задачи, график смен, уведомления и AI-ассистент в одном приложении.

**Основная логика написана на Rust.** Через чат можно предложить создание задачи или графика, проверить конкретные параметры и применить их кнопкой подтверждения. Локальная модель подключается через Ollama; данные приложения хранятся в PostgreSQL.

> Для запуска нужен работающий Rust-сервер, PostgreSQL и Ollama. Это локальное приложение, а не готовый публичный веб-сервис. Открывать HTML двойным кликом не нужно.

## Первые шаги в приложении

1. Создать задачу обычным сообщением в AI-ассистенте.
2. Убедиться, что до подтверждения задачи в списке нет.
3. Проверить карточку, нажать **«Подтвердить»** и открыть созданную задачу по ссылке.
4. Попросить график на пять дней, подтвердить единый пакет смен и открыть нужную неделю.
5. В том же диалоге снова запросить задачу: предыдущий разговор о графике не должен менять тип новой операции.
6. Показать отказ от предложения, сохранение истории после перезагрузки и защиту ручных правок от устаревших предложений.

Примеры запросов для знакомства с приложением приведены ниже. Полный сценарий проверки с ожидаемыми результатами — **[TESTING_RU.md](TESTING_RU.md)**.

## Возможности

| Раздел | Что доступно |
| --- | --- |
| AI-ассистент | Диалоги с историей, ответы по рабочим данным, предложения и отдельное подтверждение действий |
| Задачи | Создание, изменение срока/ответственного/приоритета/статуса, комментарии, напоминания, удаление |
| График работы | Смены, пакетное планирование, проверка отдыха от 12 часов, публикация и отклонение предложений |
| Встречи | Создание из текста, обработка в протокол, загрузка материалов через экран встречи, удаление |
| Команда | Справочник сотрудников и добавление новых записей |
| Уведомления | Уведомления внутри приложения, отметки прочтения |
| Настройки | Компания, часовой пояс и разрешённые параметры работы помощника |

Создание сотрудника добавляет запись справочника; оно не создаёт учётную запись и не отправляет приглашение по почте. Новую учётную запись создают на странице регистрации.

## Требования

- Актуальный **Rust stable** и Cargo: https://rustup.rs/.
- **PostgreSQL 14+**, работающая база и известные параметры подключения: https://www.postgresql.org/download/.
- **Ollama** с моделью, поддерживающей структурированный JSON: https://ollama.com/download.
- Современный браузер.
- Для Windows и Rust MSVC: C++ Build Tools / Visual Studio Build Tools, если установщик Rust сообщает об отсутствии компилятора или linker.

Модель по умолчанию — `qwen2.5:7b`. Она требует нескольких гигабайт свободной памяти; GPU ускоряет ответы. На CPU подготовка ответа может занять заметное время. Для первого запуска попробуйте составить график одному сотруднику на пять дней.

**Node.js и Python для работы приложения не нужны.** Python используется только в дополнительных автоматических тестах.

## Установка и запуск

### 1. Получите проект

```powershell
git clone https://github.com/kirieshka800/fotoprin.git
cd fotoprin
```

Если репозиторий приватный, сначала получите доступ и авторизуйтесь в GitHub. Альтернатива: **Code → Download ZIP**, распакуйте архив и откройте терминал в папке, где находится `Cargo.toml`.

### 2. Подготовьте PostgreSQL

Запустите службу PostgreSQL. Для новой установки можно создать отдельного пользователя и базу. В pgAdmin, подключившись администратором к базе `postgres`, выполните **по отдельности**:

```sql
CREATE USER fotoprint_user WITH LOGIN PASSWORD 'CHANGE_ME';
```

```sql
CREATE DATABASE fotoprint OWNER fotoprint_user;
```

Замените `CHANGE_ME` собственным паролем и используйте тот же пароль в `.env`. Эти команды нужны только для новой базы. Если у вас уже есть рабочая база проекта, используйте её прежнюю строку подключения.

### 3. Создайте `.env`

Скопируйте `.env.example` в `.env` рядом с `Cargo.toml`:

```powershell
Copy-Item .env.example .env
```

При обновлении существующей установки сохраняйте свой `.env`: команда копирования предназначена для первой настройки.

Пример содержимого:

```dotenv
DATABASE_URL=postgres://fotoprint_user:CHANGE_ME@localhost:5432/fotoprint
OLLAMA_URL=http://localhost:11434
OLLAMA_MODEL=qwen2.5:7b
OLLAMA_NUM_CTX=32768
DEFAULT_USER_ROLE=manager
```

- В `DATABASE_URL` укажите своего пользователя, пароль, адрес, порт и имя существующей базы.
- Пароль в URL должен быть URL-кодирован, если содержит специальные символы вроде `@`, `#` или `%`.
- Имя файла — **`.env`**, без дополнительного `.txt`.
- `OLLAMA_URL` принимает базовый адрес или полный адрес `/api/generate`.
- Размер контекста `32768` нужен для рабочих данных и схемы действий; для него требуется дополнительная память.
- `DEFAULT_USER_ROLE` используется существующей обработкой протоколов; права действий ассистента проверяются по серверной сессии вошедшего пользователя.

Настоящий `.env` и пароли не включены в репозиторий. Не присылайте их в сообщения или отчёты об ошибках.

### 4. Запустите Ollama и загрузите модель

```powershell
ollama pull qwen2.5:7b
ollama list
```

Ollama должна оставаться запущенной. Если приложение/служба Ollama ещё не работает:

```powershell
ollama serve
```

Если Ollama сообщает, что порт 11434 занят уже работающим сервисом, второй экземпляр не нужен.

### 5. Запустите Rust-сервер

Из папки с `Cargo.toml`:

```powershell
cargo run
```

При первом запуске Cargo скачает зависимости и соберёт программу. Миграции базы применяются автоматически. После успешного запуска появится сообщение:

```text
Сервер запущен на http://127.0.0.1:8081
```

Оставьте терминал открытым. Остановка сервера — **Ctrl+C**.

### 6. Откройте приложение

**http://127.0.0.1:8081**

Зарегистрируйтесь или войдите в существующую учётную запись. Прямая ссылка на ассистента:

**http://127.0.0.1:8081/assistant.html**

Это основной обновлённый интерфейс. Параметр `?v=2` не требуется. Страницы и скрипты отдаются с `Cache-Control: no-store`; после перехода со старой установки один раз нажмите **Ctrl+F5**.

Первая учётная запись в пустой базе получает роль администратора. В исходном приложении последующие регистрации по умолчанию создаются с ролью `manager`; это следует учитывать при настройке доступа. Для проверки роли обычного сотрудника её нужно отдельно настроить администратором.

## Примеры запросов к AI-ассистенту

Создайте новый диалог. Относительные даты рассчитываются от текущей даты и часового пояса программы.

### Создать задачу

> Создай задачу «ТЕСТ: проверить качество печати заказа №125» без ответственного, со сроком завтра в 15:00 и высоким приоритетом. Описание: проверить цветопередачу и отсутствие дефектов.

Ожидание: карточка **«Создать задачу»**. Проверьте параметры, подтвердите и откройте результат. Не должно быть карточек публикации графика или чтения уведомлений.

### Составить график себе

> Создай мне график на следующую неделю: с понедельника по пятницу, каждый день с 09:00 до 18:00, без перерывов.

Ожидание: одна карточка **«Сохранить смены без публикации»**, внутри пять смен. После подтверждения смены появятся в графике. Ссылка на результат откроет нужную неделю.

### Изменить задачу

Узнайте числовой ID задачи из адреса `task.html?id=...`. Замените `ID` этим числом:

> Перенеси задачу ID на послезавтра в 16:00 и измени приоритет на «Срочный».

Ожидание: изменение существующей задачи после подтверждения.

### Проверить отсутствие скрытых изменений

> Создай задачу «ТЕСТ: предложение для отказа» без ответственного, на завтра в 12:00, обычный приоритет.

Нажмите **«Отклонить»**. Задача не должна появиться в списке.

### Открыть раздел

> Открой встречи.

Ожидание: ссылка на раздел; подтверждать изменение данных не требуется.

Если модель просит необходимые сведения, ответьте в том же диалоге. Если карточка не соответствует запросу, отклоните её и сохраните пример для отчёта об ошибке.

## Как устроено подтверждение

Модель формирует данные предложения; Rust проверяет тип операции, поля, сотрудников, даты и права. Браузер показывает сохранённые сервером параметры. Кнопка отправляет ID предложения — параметры на этапе подтверждения клиент не подменяет.

Изменение рабочих данных, история, уведомления и статус предложения фиксируются одной транзакцией. Повторное подтверждение возвращает прежний результат. Снимки записей защищают ручные правки: если данные изменились после подготовки карточки, требуется новое предложение.

Пакет смен применяется целиком. При недостаточном отдыхе или другой ошибке частичного сохранения не происходит. Публикация графика — отдельное подтверждаемое действие.

## Обновление проекта

Сначала остановите старый сервер. Для установки через Git:

```powershell
git pull
cargo run
```

Для ZIP-установки распакуйте новую версию отдельно, перенесите собственный `.env` и папку `uploads`. Используйте прежнюю базу, если нужно сохранить данные. Старые браузерные демо-диалоги не импортируются; новые диалоги хранятся в PostgreSQL.

При обновлении не заменяйте существующие миграции произвольными версиями и не удаляйте историю `_sqlx_migrations`. Правило `.gitattributes` сохраняет исходные байты SQL-файлов, поскольку SQLx учитывает окончания строк в контрольных суммах.

## Если не запускается

| Сообщение или симптом | Что проверить |
| --- | --- |
| `DATABASE_URL ... NotPresent` | `.env` находится рядом с `Cargo.toml`, содержит `DATABASE_URL`, имя не заканчивается на `.txt`; запуск выполняется из папки проекта |
| `28P01: password authentication failed` | Пользователь и пароль в URL. Подключение pgAdmin под `postgres` не проверяет пароль другого пользователя `fotoprint_user` |
| pgAdmin подключается, приложение — нет | Сравните пользователя, базу, адрес и порт. Переменная окружения `DATABASE_URL` имеет приоритет над `.env` |
| Нечитаемая ошибка PostgreSQL / `non-UTF-8 string` | Ошибка сервера скрыта локалью сообщений Windows. Посмотрите журнал PostgreSQL; подробный способ диагностики приведён ниже |
| `VersionMismatch` | Файл ранее применённой миграции отличается, иногда из-за LF/CRLF. Сверьте SHA384 и сохранённую контрольную сумму, восстанавливайте исходные файлы, сохраняя данные базы |
| `failed to remove ... fotoprint-backend.exe`, отказано в доступе | Остановите запущенный старый сервер перед пересборкой |
| Нет связи с Ollama | Проверьте службу, порт 11434, `OLLAMA_URL` и наличие модели в `ollama list` |
| Ответ модели занимает слишком много времени | Сократите запрос/период графика, проверьте свободную память и загрузку Ollama |
| Старый чат с «Прикрепить» | Откройте адрес Rust-сервера, нажмите Ctrl+F5, проверьте обновление файлов и настройку `STATIC_DIR` |

Чтобы убрать старую переменную только из текущего PowerShell и перечитать `.env`:

```powershell
Remove-Item Env:DATABASE_URL -ErrorAction SilentlyContinue
cargo run
```

Чтобы остановить оставшийся процесс программы:

```powershell
Get-Process -Name fotoprint-backend -ErrorAction SilentlyContinue | Stop-Process -Force
```

Чтобы сервер явно использовал `static` из текущей папки:

```powershell
$env:STATIC_DIR = (Resolve-Path .\static).Path
cargo run
```

При ошибке кодировки сообщения PostgreSQL администратор может временно переключить язык серверных сообщений. В pgAdmin выполните **отдельно** `ALTER SYSTEM SET lc_messages = 'C';`, затем отдельно `SELECT pg_reload_conf();`. Это изменение языка сообщений всего сервера; после него повторите подключение и исправьте указанную конкретную причину.

Предупреждения `unused import` и `dead_code` сами по себе не мешают запуску. Ошибка запуска находится после строки `Running ...`.

## Ограничения

- Ответы настоящей модели могут содержать ошибки. Окончательное решение принимает пользователь по параметрам карточки. Сервер ограничивает явные команды поддерживаемыми типами действий и отклоняет неверные параметры.
- Контекст не является полным экспортом базы: используются ограниченные выборки сотрудников, задач, встреч и смен. Для конкретной старой записи укажите ID или откройте раздел.
- На один план — до 140 смен за период до 32 дней. Между соседними сменами сотрудника требуется минимум 12 часов отдыха, в том числе через границу недели.
- Почта и Telegram в исходной версии не подключены к реальной отправке. Напоминания доставляются уведомлениями внутри приложения, даже если в настройке выбран внешний канал.
- Встреча из чата обрабатывает переданный текст и создаёт протокол; задачи из неё автоматически не добавляются. Для файлов/аудио используйте отдельный экран. Распознавание аудио зависит от настроенного существующего сервиса транскрибации.
- Программа использует общее рабочее пространство. История чатов приватна владельцу; полного разделения организаций в этой версии нет.
- Сервер слушает `127.0.0.1:8081` для локального использования. Публичное развёртывание требует отдельной настройки.

## Проверки

```powershell
cargo test
```

Это Rust-тесты проверки действий, дат и общей логики. Отчёт последней проверки: [CHECKS.md](CHECKS.md).

HTTP- и браузерные сценарии выполняются на настоящей отдельной PostgreSQL и с подставным Ollama. Они проверяют подтверждение, отказ, права, повторные запросы, откат, кеширование и интерфейс. Качество понимания настоящей моделью проверяйте ручными сценариями [TESTING_RU.md](TESTING_RU.md).

**Тесты создают пользователей и записи, меняют настройки. Используйте только отдельную тестовую базу.**

Терминал 1:

```sh
python3 tests/fake_ollama.py
```

Терминал 2 (пример для shell Linux/macOS):

```sh
DATABASE_URL=postgres://postgres:password@localhost/fotoprint_test \
OLLAMA_URL=http://127.0.0.1:11435 OLLAMA_MODEL=test cargo run
```

В Windows задайте эти переменные через `$env:ИМЯ = 'значение'` перед `cargo run`.

Терминал 3:

```sh
ASSISTANT_TEST_DATABASE_URL=postgres://postgres:password@localhost/fotoprint_test \
python3 tests/assistant_integration.py
```

Для браузерных тестов установите Python Playwright и Chromium, задайте `CHROMIUM_PATH` путём к установленному Chromium, затем запустите `python3 tests/assistant_browser.py`. При отсутствии `psql` в PATH задайте переменную `PSQL` полным путём к нему.

## Технологии и структура

- **Rust / Axum / Tokio** — HTTP-сервер и действия ассистента.
- **SQLx / PostgreSQL** — данные, миграции и транзакции.
- **Ollama** — локальная модель и структурированные предложения.
- **HTML / CSS / JavaScript** — существующий веб-интерфейс.

`src/assistant/` — планирование, допустимые операции, карточки и подтверждение; `src/api/` — задачи, график и уведомления; `src/meetings.rs` — обработка встреч; `static/` — интерфейс; `migrations/` — схема базы; `tests/` — дополнительные проверки. Контракты API описаны в [BACKEND.md](BACKEND.md).

## Аудио и Whisper

Полная настройка Docker-сервиса, переменных окружения и проверка распознавания описаны в [AUDIO_SETUP.md](AUDIO_SETUP.md). После обработки аудио его текст используется для протокола, вопросов по встрече и контекста AI-ассистента. Ошибка Whisper показывается явно; сохранённую запись можно распознать повторно кнопкой «Распознать аудио».
