# Фотопринт AI — Rust

Сервер: **Rust + Axum + SQLx**. База: PostgreSQL. Локальная модель: Ollama. Интерфейс: существующие HTML/CSS/JavaScript, без отдельного Python/Node-сервера.

## Запуск

1. Установите актуальный Rust stable, PostgreSQL 14+ и Ollama.
2. Создайте базу PostgreSQL `fotoprint`.
3. Скопируйте `.env.example` в `.env`, укажите собственные данные подключения. При обновлении существующего проекта сохраните свой `.env` и свою базу.
4. Загрузите модель: `ollama pull qwen2.5:7b`. Убедитесь, что Ollama запущена (`ollama serve`, если сервис ещё не работает).
5. Из папки с `Cargo.toml` выполните `cargo run`.
6. Откройте `http://127.0.0.1:8081`, войдите или зарегистрируйтесь и перейдите в «AI-ассистент».

Миграции выполняются автоматически. Новые таблицы диалогов создаются миграциями 007–009; прежние миграции не изменены. Не запускайте HTML двойным кликом: интерфейс использует сессионную cookie Rust-сервера.

`OLLAMA_URL` принимает базовый адрес (`http://localhost:11434`) либо полный адрес `/api/generate`. `OLLAMA_NUM_CTX=32768` задаёт размер контекста; для него нужно достаточно памяти. Если модель отвечает слишком долго, уменьшите период графика или объём запроса. Настоящая модель должна поддерживать JSON Schema в Ollama.

## Что умеет ассистент

- Создавать задачи, менять название, описание, срок, ответственного, статус и приоритет, удалять задачи.
- Добавлять комментарии и настраивать напоминания.
- Составлять смены по вашим условиям, проверять отдых от 12 часов, сохранять график без публикации, публиковать и отклонять предложения.
- Отвечать по встречам, протоколам, сотрудникам, задачам, сменам и доступным документам.
- Добавлять сотрудников, создавать встречи из текста, удалять встречи.
- Отмечать уведомления прочитанными, менять разрешённые настройки и открывать разделы программы.

Любое изменение сначала показывается **карточкой с параметрами**. Кнопка «Подтвердить» применяет сохранённое предложение; «Отклонить» оставляет данные как есть. Сообщение «да» в чате само по себе ничего не применяет. После выполнения появится ссылка на результат.

Например:

- «Создай задачу проверить заказ к 20 декабря в 15:00, приоритет высокий, без ответственного».
- «Перенеси задачу FP-123 на завтра к 18:00».
- «Составь Ивану Петрову график на следующую неделю: с понедельника по пятницу с 09:00 до 18:00».
- «Опубликуй график на неделю с 14 декабря».
- «Покажи просроченные задачи».
- «Отключи напоминания».

При неоднозначном имени или недостаточных сведениях модель должна уточнить запрос. Проверяйте параметры карточки: модель может ошибиться. Если запись изменилась после подготовки предложения, сервер попросит подготовить новое и сохранит ручные изменения.

## Права и ограничения

История хранится в PostgreSQL и доступна только владельцу учётной записи. Роль берётся из действующей серверной сессии. Управление графиком, настройками и сотрудниками, удаление задач и встреч доступны руководителю. Обычные операции с задачами сохраняют существующую модель доступа программы.

Смены одного предложения подтверждаются целиком: при ошибке любой смены весь пакет откатывается. На один запрос — до 140 смен за период до 32 дней. Публикация — отдельное подтверждение. Повторное нажатие на подтверждение возвращает сохранённый результат и не создаёт дубликаты.

Добавление сотрудника создаёт запись справочника, а не учётную запись и не приглашение по почте. Создание встречи из чата обрабатывает предоставленный текст и создаёт протокол; задачи из него автоматически не добавляются. Для файлов и аудио используйте ссылку «Загрузить текст или аудио встречи».

Напоминания сейчас доставляются **уведомлениями внутри приложения**. Выбранные каналы почты/Telegram сохраняются, но внешняя отправка в исходном проекте не подключена. Ассистент не подключает внешние интеграции и не повышает права пользователей.

Контекст модели ограничен: подходящие и ближайшие задачи, сотрудники, последние встречи, смены от 14 дней назад до 60 дней вперёд. Это не полный экспорт базы. Если нужная запись не найдена, укажите её ID/код или откройте соответствующий раздел. Старые демо-диалоги из localStorage не импортируются: новые реальные диалоги хранятся отдельно.

## Проверки

`cargo test` — Rust-проверки валидации и дат.

Интеграционные и браузерные тесты запускайте **только на отдельной тестовой базе**, потому что они создают пользователей, задачи, смены и меняют настройки:

```sh
# Терминал 1: тестовый ответ модели (не настоящая нейросеть)
python3 tests/fake_ollama.py

# Терминал 2: Rust-сервер на отдельной базе
DATABASE_URL=postgres://postgres:password@localhost/fotoprint_test \
OLLAMA_URL=http://127.0.0.1:11435 OLLAMA_MODEL=test cargo run

# Терминал 3: HTTP-проверки
ASSISTANT_TEST_DATABASE_URL=postgres://postgres:password@localhost/fotoprint_test \
python3 tests/assistant_integration.py

# Браузер: установите Python Playwright и Chromium
python3 -m pip install playwright
python3 tests/assistant_browser.py
```

Для браузерных тестов `CHROMIUM_PATH` может указывать путь к Chromium. Python используется только для тестов; он не нужен для запуска программы.

Проверены подтверждение/отказ, повторное и одновременное нажатие, откат графика целиком, смены через границу недели, защита чужих диалогов, повторная проверка роли, устаревшие данные, ограничение контекста, параллельные диалоги, экран телефона и отсутствие ошибок JavaScript. Интеграционные тесты используют подставной Ollama; качество понимания запросов настоящей моделью проверяется отдельно на вашей машине.
